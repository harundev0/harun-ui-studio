# Conditional skill routing

Use installed skills as references, not a bundle to load on every request. The core already captures routine Caveman/Ponytail preferences. Usually zero or one additional skill is enough; add another only for a distinct unresolved concern. Never re-read a skill already loaded in context. If unavailable, use repository evidence and report the missing capability; do not install blindly.

## Requested design sources

| Source | Load when | Boundary |
| --- | --- | --- |
| `ui-ux-pro-max` | A specific UX question, unfamiliar platform, or genuinely absent design system | Search narrowly; repository tokens win. Verify recommendations before persisting. |
| `emil-design-eng` | Interaction timing, gesture behavior, component feel, motion review | Existing timings first; no automatic animation. UI review uses Before/After/Why table. |
| `design-taste-frontend` | Marketing/portfolio direction or expressly requested visual overhaul | Not a dashboard architecture guide. Existing branding overrides anti-default preferences. |
| `design-taste-frontend-v1` | User explicitly requests legacy compatibility | Do not co-load v1 and v2. Borrow isolated patterns only; no mandatory perpetual animation. |
| `impeccable` | Targeted audit, polish, typography/layout correction, or new visual direction | Follow its context setup and applicable reference; preserve scope and cap polish passes. |
| `caveman` | User asks for stricter chat compression | Concise chat only; full grammar in copy/docs and complete handoff. |
| `ponytail` | A concrete simplification/dependency decision | Reuse/native first; never simplify away requirements or accessibility. |

For `ui-ux-pro-max`, locate its installed base directory. Check Python first. If Python is unavailable, use its documented reference fallback; do not install Python automatically. Existing UI issues use a domain query; known stacks use a stack query. `--design-system` is reserved for a genuine system-wide need. Do not overwrite established design records with generated recommendations.

## ECC coding support

These installed entries carry ECC provenance; invoke only the applicable one:

| Skill | Actual need |
| --- | --- |
| `frontend-patterns` | React/Next composition, state ownership, or frontend data-flow choices |
| `react-patterns` | Hooks, React boundaries, Suspense, accessible component composition |
| `vue-patterns`, `angular-developer`, `react-native-patterns` | Use only the detected framework; verify installed source/provenance separately |
| `frontend-a11y` | Forms, focus, dialogs, keyboard navigation, semantic controls |
| `react-performance` | Measured render/bundle/data-loading issue in React/Next |
| `react-testing` | Meaningful component/hook behavior tests |
| `e2e-testing` | Playwright flow coverage, stable waits, screenshots, test artifacts |
| `contract-first` | Read existing contracts; describe consumer requirements and pending backend handoff |
| `coding-standards` | Naming/readability review not covered by the stack's conventions |

`contract-first` provider implementation/generation steps are outside this skill's scope. Backend skills, backend agents, endpoint scaffolding, and deployment workflows are not dispatched. Example snippets in upstream skills do not authorize replacement of installed clients or patterns.

For an actual bug use `systematic-debugging`; for unfamiliar APIs use `documentation-lookup`; before success claims use `verification-before-completion`. These are conditional tools, not mandatory extra context for a simple spacing edit.

## Conflict resolution

Repository rules and the user's task outrank borrowed style preferences. Accessibility, product truth, and frontend-only ownership constrain all design choices. Preserve existing fonts, purple branding, Lucide, CSS, Vue, and tokens when present. v2 is the default taste reference; v1 is legacy opt-in. No forced new design system, dual theme, image generation, or motion package for a narrow refinement.

New images and public metrics must be grounded in supplied assets/data. Label fixtures clearly; invented testimonials or customer logos are never production evidence.
